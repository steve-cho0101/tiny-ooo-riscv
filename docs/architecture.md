# Architecture

Status: every block is implemented, and the full CPU runs GCC-compiled C in
simulation. `prf` has been hardened in a test harness, see
[Hardening results](#hardening-results). The full CPU has not been hardened, and
nothing has run on real hardware or against a real RP2350.

## Goals

In priority order:

1. Correct execution of GCC-compiled C programs.
2. Genuine out-of-order execution with in-order retirement.
3. A design that fits and passes the Tiny Tapeout flow.
4. Performance, which is not a goal. IPC will not beat a simple pipeline.

## Summary

| Item | Decision |
|---|---|
| ISA | RV32E, see [isa.md](isa.md) |
| Width | 1 dispatch, 1 issue, 1 retire per cycle |
| Physical registers | 19 × 32 (15 architectural + 4 in flight), latch array |
| ROB | 4 entries, control only, no data |
| Rename | RAT plus ROB-slot swap, no free list |
| Reservation stations | 2 entries, tags only, shared by ALU and memory ops |
| Execution | One ALU with barrel shifter, one LSU slot |
| Control flow | No prediction, dispatch stalls until resolved |
| Memory | External, 64 KiB, emulated by the demo board RP2350 |
| Target | TTSKY27a (May 2027), 3×2 tiles, 2×2 as stretch |
| Clock | 10 MHz STA target or lower, generated by the MCU |

## Block diagram

```text
 ui_in ─► Fetch queue(2) ─► Decode ─► Rename/ROB ─► RS(2) ─► PRF read ─► ALU ──┐
              ▲               │       (RAT+slots)              │               │
              │ redirect      │ LUI/AUIPC/link                 └► LSU slot ──┐ │
              │               ▼                                              ▼ ▼
 Bus ◄────────┴──────── PRF write ◄──────────── result bus (LSU priority) ◄──┴─┘
 (uo_out, uio)                        └─► wakeup RS, mark ROB done
```

## Pipeline timing

| Cycle | What happens |
|---|---|
| D | Decode, rename, allocate ROB slot, insert into RS |
| E | RS selects a ready entry, PRF read, ALU computes, result captured in the write-back register |
| W | Write-back register drives wakeup and ROB done. Latches open in the low phase |
| E+2 | Earliest issue of a dependent instruction |

A dependent ALU instruction therefore issues two cycles after its producer.
This costs no throughput, because fetch delivers at most one instruction every
four cycles. It also removes any half-cycle path from the PRF read, and it means
the flop fallback has identical timing.

## Rename: the ROB-slot swap

Each ROB slot permanently owns one physical register in `slot[i].p`.

At reset, `RAT[xN]` maps x1..x15 to p0..p14, and slots 0..3 own p15..p18.

Allocating an instruction with `rd != x0` into slot `t`:

```text
psrc1 = RAT[rs1], psrc2 = RAT[rs2]    // read BEFORE the swap
pdst  = slot[t].p
slot[t].p = RAT[rd]                   // slot now holds the old mapping
RAT[rd]   = pdst
ready[pdst] = 0
```

Retirement touches no register state. It only advances the ROB head, and that
slot's `p` becomes the register handed out at its next allocation.

Why this is safe: `slot[t].p` holds the previous mapping of `rd`. Its only
possible readers and its writer are older than the instruction in slot `t`, and
retirement is in order, so they have all finished before the register is reused.

Invariants, which RTL verification must check every cycle:

- `{RAT entries} ∪ {slot p fields}` is a permutation of p0..p18.
- A register is never allocated while a writer to it is in flight.
- Instructions with `rd == x0` do not swap.

Sources equal to x0 use a reserved tag that reads as zero and is always ready.

Evidence so far: a randomized Python model retired 4,000,000 instructions over
200 seeds, with 1,269,073 issues ahead of an older instruction, and every result
matched in-order execution. Two deliberately broken variants failed: reading
sources after the swap deadlocked, and skipping the slot update broke the
permutation invariant. This model covers rename only. It has no memory, no
branches and no cycle timing.

The RAT reflects architectural state whenever the ROB is empty. There is no
retirement RAT because nothing is ever flushed. If speculation is added later,
recovery means walking the ROB from tail to head and undoing each swap.

## ROB

Each entry holds the slot register `p`, `done`, and a halt flag. Stores need no
flag, because the LSU compares its ROB tag with `head_tag`.

- `alloc_ready` is `!full`. It does not look at same-cycle retirement, so there
  is no combinational path from retire to dispatch. A full ROB loses one cycle.
- Allocation and retirement can happen in the same cycle when neither full nor
  empty, and the count then stays the same.
- Retirement frees at most one entry per cycle, in order, when the head is done.

Every instruction takes a ROB slot, including branches and stores.

## Reservation stations

Each entry holds: valid, two source tags with ready bits, class, ALU op, memory
op, `pdst`, ROB tag, 12-bit immediate, and operand-B select.

- Selection is fixed priority. An older instruction cannot starve, because a
  full ROB stops new instructions and the entry then issues.
- **Lost wakeup rule:** the ready bits written at rename must include the
  write-back in the same cycle. Otherwise an instruction renamed while its
  producer is in W waits forever.
- Issue is held for one cycle when the LSU needs the write port. Wakeups still
  land during a hold.
- Issue reads only the stored ready bits, so an instruction cannot issue during
  its producer's W cycle, while the latch is open.
- `alloc_ready` ignores a same-cycle issue, as in the ROB, so there is no
  combinational path from `issue_hold` to dispatch.

## Write port

There is one PRF write port and one result bus. Priority is LSU, then ALU, then
dispatch write. A dispatch write cannot be starved, because the RS drains and
stops refilling while dispatch is stalled.

The ROB's complete port shares this bus, so a result carries its ROB tag. A store
has nothing to write, so `lsu` sends `PTAG_ZERO`, which reads as zero and touches
no register. That way a store finishing can never collide with an ALU completion,
and no second arbiter is needed. `result_valid` from `lsu` is `issue_hold`.

## Dispatch writes

LUI, AUIPC and the link value of JAL and JALR are known at decode. The front-end
adder computes them and writes them through the write port, and their ROB entry
is done at allocation. This keeps the PC out of the RS, and the RS immediate at
12 bits.

## Control flow

No younger instruction is dispatched while control flow is unresolved, so nothing
in the ROB is ever speculative.

| Instruction | Handling |
|---|---|
| JAL | Target computed at decode, redirect immediately |
| Branch | Compare in ALU. The instruction stays at the head of the fetch queue, which keeps its PC and immediate with no extra storage. Taken: redirect to PC + imm. Not taken: dequeue and continue, the stream is already correct |
| JALR | Link is a dispatch write. ALU computes rs1 + imm, and the result goes to redirect instead of the write port |
| ECALL, EBREAK, illegal | Dispatch stops. At retirement, send a HALT frame and freeze |

Since the MCU streams instructions, the core keeps only the decode PC.

## Memory ordering

- A memory instruction can dispatch only when no other memory instruction is in
  flight, so memory operations stay in program order. No disambiguation and no
  store forwarding exist.
- The ALU computes `rs1 + imm`. The LSU captures the address, plus `rs2` for
  stores, when the instruction issues.
- **Loads** start as soon as they issue. This is safe because nothing in flight
  is speculative and no older store is pending.
- **Stores** wait until they are at the ROB head, so memory can never change
  early. The store is marked done when its frame has been sent, and then retires.
- `lsu` uses one 32-bit register both ways: store bytes shift out low first, and
  load nibbles shift in. It counts the 8 nibbles, and `load_done` tells `bus_if` to
  clear its busy bit.

No deadlock arises: a store at the head has nothing older to wait for.

## External bus

The MCU generates the chip clock, holds all memory and answers requests.
Latencies are counted in chip cycles, so the pad speed limits do not apply.
Transfers happen on the rising clock edge.

| Pins | Direction | Name | Use |
|---|---|---|---|
| `ui_in[7:0]` | In | `I_DATA` | Instruction bytes, least significant first |
| `uo_out[7:0]` | Out | `O_DATA` | Outgoing frames |
| `uio[3:0]` | In | `D_DATA` | Load data, least significant nibble first |
| `uio[4]` | In | `I_VALID` | `I_DATA` is valid |
| `uio[5]` | In | `D_VALID` | `D_DATA` is valid, or redirect acknowledge |
| `uio[6]` | Out | `O_VALID` | `O_DATA` is valid |
| `uio[7]` | Out | `I_READY` | Core can accept an instruction byte |

`uio_oe` is the constant `8'b1100_0000`.

### Outgoing frames

Every frame is a header byte, then the address low byte, then the address high
byte. Stores add the data bytes.

| Header bits | Field |
|---|---|
| `[7:6]` | Type: 00 redirect, 01 load, 10 store, 11 halt |
| `[5:4]` | Size for stores: 0 byte, 1 halfword, 2 word |
| `[3:0]` | Halt reason: 0 ECALL, 1 EBREAK, 2 illegal. Otherwise 0 |

| Frame | Response from MCU |
|---|---|
| Redirect | One `D_VALID` pulse, the acknowledge. `D_DATA` is ignored |
| Load | 8 nibbles of the word at `addr & ~3`. The LSU extracts and extends |
| Store | None. Carries `1 << size` data bytes |
| Halt | None. Address field is 0 |

### Rules

- The MCU handles frames strictly in order.
- A response can start no earlier than the cycle after the last byte of its frame.
- **At most one load or redirect is outstanding at a time.** A pending load
  delays a redirect, and the reverse. This needs one busy bit, because the core
  always knows what the next `D_VALID` means. Stores do not count, as they have
  no response. This cannot deadlock, since the MCU always answers.
- **Redirect handshake:** `I_READY` stays low from the redirect decision until
  the acknowledge. The MCU withdraws stale bytes before it acknowledges, and the
  next byte after the acknowledge is the first byte at the target. The fetch
  queue is flushed at the acknowledge. Without this handshake, a byte launched
  before the MCU saw the frame would misalign the stream.
- After reset is released, the MCU streams from address 0 with no redirect.

### Latency

| Operation | Minimum cycles |
|---|---|
| Instruction fetch | 4 |
| Load | 11, plus MCU turnaround |
| Store | 4 to 7 |

These two paths are separate so that fetch continues during a load. Younger
instructions can then arrive, execute and finish before the load does. On a
shared bus, the window would be empty while a load was outstanding.

### Program flow

1. MCU holds `rst_n` low, then loads the program into its own memory.
2. MCU releases reset and streams from address 0.
3. The program runs. Every store is visible to the MCU.
4. An exit routine stores any registers of interest, then executes ECALL.
5. MCU sees the HALT frame. Only reset restarts the core.

State after halt is precise, because everything older has retired.

## Modules

| Module | Purpose | Main interface |
|---|---|---|
| `fetch` | Byte assembly, 2-entry queue, decode PC | Bytes in, `redirect`, `instr_valid/ready` |
| `decode` | Combinational decode | `instr` → `uop` (class, rd, rs1, rs2, imm, illegal) |
| `rename_rob` | RAT, ROB, swap | `alloc`, `complete(rob_tag)`, `retire` |
| `issue_queue` | 2-entry RS | `alloc`, `wakeup(ptag)`, `issue` |
| `prf` | Registers and ready bits | 2 reads, 1 write. Latch or flop by parameter |
| `alu` | Combinational | `(op, a, b)` → `(y, branch_taken)` |
| `lsu` | One slot, byte alignment | `at_rob_head`, connects to `bus_if` |
| `bus_if` | Frames, arbitration, busy bit | The pins above |

Class, ALU and halt codes live in `src/uop_pkg.sv`. Use `uop_pkg::NAME` in full,
because the Yosys `read_verilog` parser in the flow rejects `import`.

`decode` reports x0 for any register field the instruction does not use, so rename
gives it the always-ready zero tag and never renames from stray bits.

## Area budget

Measured with Yosys 0.70 against `sky130_fd_sc_hd__tt_025C_1v80`. This is synthesis
only, not hardened, and has no timing analysis. `rename_rob` is the real RTL.
Every other row is a throwaway probe approximating that block's storage and
muxing, and **probes can read low**: the `rename_rob` probes predicted 5,832 µm²,
because they missed the third RAT read port and the swap paths.

| Block | µm² |
|---|---:|
| Register storage, 19×32 latches, 2R1W | 15,848 |
| `rename_rob`: RAT and ROB (real RTL) | 12,189 |
| RS, 2 entries | 2,786 |
| ALU with barrel shifter | 4,845 |
| Front end, 2-entry queue | 4,026 |
| Byte-serial LSU | 3,129 |
| **Total** | **42,823** |
| With 15% glue logic (assumed) | 49,246 |

Die sizes come from the TT tools (`tech/sky130A/tile_sizes.yaml`): 1×1 is
17,955 µm², 1×2 is 36,347 µm², 2×2 is 75,603 µm² and 3×2 is 114,858 µm². That
makes the estimate 65% of a 2×2 and 43% of a 3×2.

As a pessimistic bound, doubling the RS, ALU, front end and LSU probes gives a
design with glue logic of about 88% of 2×2 and 58% of 3×2. The PRF probe is left
as is, since it is mostly storage.
That is why 3×2 stays the plan, and 2×2 now looks unlikely without the saving
below.

Possible saving in `rename_rob`, not adopted: fetch delivers at most one
instruction every four cycles, so rename could read rs1, rs2 and rd over three
cycles through one RAT read port. An area-only variant measured 7,710 µm², saving
4,479 µm². Removing the reset from the RAT and slots saved nothing.

Comparisons from the same probes:

| Alternative | Result |
|---|---|
| 15×32 flop registers | 21,680 µm² |
| Value-capturing ROB and RS, as in textbook Tomasulo | 7,702 + 7,991 µm², total design about 77% of 2×2 (probes only) |
| Single PRF read port | Saves about 2,900 µm², but needs an operand latch and an extra cycle. Rejected |
| Iterative shifter | Saves 725 µm². Rejected |
| Nibble-serial datapath | Saves about 5,900 µm², but ties all logic to a rotation phase. Fallback only |

Real RTL, by the same method, replaces those probes:

| Block | µm² |
|---|---:|
| `alu` | 4,394 |
| `issue_queue` | 3,358 |
| `lsu` | 3,184 |
| `fetch` | 2,905 |
| `decode` | 860 |
| `bus_if` | 754 |
| **Full `cpu`, flattened, with `prf` and `rename_rob`** | **45,449** |

That is below the 49,246 µm² budget, which assumed 15% glue logic.

If latches fail, 19×32 flops scale to about 27,500 µm², which is about 83% of
2×2 and 55% of 3×2 with glue logic included.

## Hardening results

Run 41170895085 attempt 2, commit `5ea6664`: `prf` plus the pin harness in
`src/project.sv`, on a 2×2 die at 10 MHz, with `PL_TARGET_DENSITY_PCT` 45. It does
not include `rename_rob` or any other CPU block.

| Check | Result |
|---|---|
| Routing | 0 DRC violations after 49 iterations in the final route |
| Precheck | All checks passed (Magic, KLayout, pins, layers, boundary) |
| LVS, antenna | Passed, 0 violating nets |
| Gate-level test | 4 of 4 passed, unit delay with no SDF, so it shows logic and not timing |
| Setup, 9 corners | 0 violations, worst slack 20.69 ns, reg-to-reg 43.65 ns |
| Hold, 9 corners | 0 violations, worst slack 0.136 ns |
| Max slew | **1,761 pins over the 0.75 ns limit** in the worst corner, up to 2.21 ns |
| Max cap | **85 pins over limit**, slow corner only |

STA does cover the latch gate race: the flop-to-latch hold paths are reported and
the tightest is 0.138 ns, and the gates have clock gating checks with 43.65 ns of
slack. The slowest latch read reaches a pin about 9 ns after the latch opens in the
slow corner, including about 2.25 ns of clock network.

The slew violations do not fail the flow and are included in the STA figures, but
they should not reach the CPU. The worst nets are the decoded PRF read selects,
each fanning out to 32 mux bits through weak `clkdlybuf4s25_1` buffers.

| Area | µm² |
|---|---:|
| Synthesis, harness and `prf` | 22,391 |
| Placed and routed cells | 30,467 |
| Timing repair buffers, including 83 hold buffers | 3,712 |
| Clock buffers | 2,905 |
| Core | 72,565 |

Utilization was 42%. A 1×2 at 88% could not route, with about 13,000 violations.
Hardening added 36% to synthesis area.

Runtime was 4 h 26 min on the 4-thread runner GitHub gives public repos. The same
job did not finish in 6 h on the 2-thread private runner. Most of it is a few
stubborn met1 violations, and antenna repair forces a second detailed route.

Projection for the full CPU, which is arithmetic and not a measurement: 45,449 µm²
of real RTL, plus 20% for the gap seen between this quick synthesis and the flow's,
plus 36% for hardening, gives about 74,000 µm². Assuming the 2×2 ratio of core to
die, that is about 67% of a 3×2 core and 50% of a 4×2 core. Only 42% has been proven
to route, so the first CPU build uses 4×2.

## Risks

| Risk | Status | Plan |
|---|---|---|
| Latch PRF timing and glitches | Passes STA and unit-delay gate-level test in the harness, unproven in silicon | Recheck STA in the CPU. The flop fallback passes the same CPU tests |
| SystemVerilog in the TT flow | Confirmed, through GDS and precheck | None needed |
| Area after hardening | Measured for `prf` only, CPU projected | Re-measure as blocks land. Fallbacks listed above |
| Routing time against the 6 h job limit | `prf` alone took 4 h 26 min | Harden each new block early. Allow more room than area alone needs |
| PRF read select slew | 1,761 pins over limit in the harness | Fix when hardening the CPU, before relying on its timing |
| RP2350 serving the bus | Unconfirmed | Check PIO on the real board. FPGA or MCU on PMOD as fallback |
| Toolchain and libgcc | Compiled C runs on the core in simulation | See [isa.md](isa.md) |

## Verification

`pytest tb` runs block tests, deliberate bug injection into every block, and whole
programs on `cpu`. `test/` runs a short program on the Tiny Tapeout pins, on RTL and
on the gate-level netlist.

Whole-program tests run on an in-order reference model, `tb/refmodel.py`, which
raises on undefined behaviour. The core must make the same stores in the same order
and halt the same way, behind `tb/mcu.py`, a Python MCU with random memory timing.
Programs come from `tb/randprog.py` and from C in `sw/`.

## Demonstrating out-of-order execution

Run a loop with a load followed by independent ALU instructions, and sweep the
MCU's load latency. In-order execution would cost latency plus the ALU work. OoO
execution should track the load latency alone until the ROB fills. The MCU can
measure this on silicon by counting clocks.
